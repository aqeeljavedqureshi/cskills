# set-priority

## Objective
Classify requirements against a defined release or milestone.

## Instructions
1. Identify the release goal, deadline, and boundaries if known.
2. Extract requirements and their agreed priority evidence.
3. Classify only confirmed decisions: Must (release-essential), Should (important, not blocking), Could (optional), Won't (excluded this release).
4. Mark undecided priorities Unconfirmed; highlight dependencies and conflicts.
5. Ask up to 3 focused questions per round and wait for stakeholder decisions.
6. Update the priorities and list unresolved decisions.

## Output
| Requirement | Priority | Rationale / evidence |
| --- | --- | --- |
Then list dependencies and open decisions.

## Boundaries
Never infer priority from technical complexity, silently decide for stakeholders, or create implementation tasks. Won't does not mean never.
